* The free decisions of #41, settled

** Directory names are English

Author instruction, 2026-08-05.
=testes/= was the only Portuguese name in the tree and it does not survive under
that name *or* that role.
It held Excel comparison workbooks, which are products; those go to =outputs/=.

The name becomes =tests/= and holds the suites — =testthat= and the like — so it
is code and is tracked, deliberately absent from the exclusion list.
The package keeps its own =ioOECD/tests/testthat/=, where =R CMD check= requires
it; the two coexist without ambiguity because both now mean tests.

This resolves the conflict #41 recorded under "=testes/= holds outputs, not
tests" by correcting the role rather than translating the name.

** Where the Stage-B reporting code lands: =scripts/=

Author decision.
=code/support_functions.R=, =generate_reports.R= and =global_variables.R= of this
repository arrive as scripts, not as a =code/= directory and not absorbed into
=ioOECD/=.

Stated plainly: this leaves roughly 1640 lines of library code outside any
package interface, which ADR-0004 argues against.
The decision is the author's and is recorded as taken, not as agreed.
*The move itself is #28, not this ticket* — nothing of Stage B was copied here.

** Where products land

=figs/=, =tabs/=, =objs/=, =reports/=, =outputs/=, all excluded.
The model folder's =reports/= and =outputs/= are kept as names: =outputs/= is the
compiled manuscript and the comparison workbooks, =reports/= the per-country
PDFs.
=figs/=, =tabs/= and =objs/= are the names the reporting code already writes to
by relative path, so keeping them costs no code change beyond #32.

** Products are regenerated, never tracked

The reason, which #29 step 3 asked for: a figure or table in history is a claim
about which code produced it, and nothing enforces that claim.
This repository tracks =tabs/*.tex= and ignores =figs/=, an inconsistency worth
not reproducing.

* =archive/= is retained, not deleted

The deletion decided on 2026-08-05 is *reversed by the author on the same day*,
after #25 measured a second objection.

The first objection was already recorded: the four =*_original= spreadsheets in
=archive/legacy_data/= all differ from the working copies in =data-raw/= that the
deposit carries, so the deposit's four external releases are not the publisher's
files and the originals are the only record of what changed.

The second, from #25: =archive/legacy_scripts/= holds *the only working code that
builds a =NIOTs= object* — =compilacao.R=, =compilacao_ICIO.R= and the
=base/*.R= chain that composes the fourteen slots in =salva_dados.R=.
=ioOECD= does not replace it: =parse_niot_tables()= returns three of the fourteen
slots, and =load_io_tables()= cannot run at all.
Deleting =archive/= would have discarded the reference implementation of the
data-construction stage.

*Residual risk, recorded and not resolved.*
=archive/= is in neither git nor the Zenodo deposit, and it was not copied here,
so its only copy is now the one on =/HDD= on this machine.
Retention preserves it from deletion, not from disk failure.
Two follow-ups remain open: whether =archive/legacy_scripts/= should be tracked
in git as the reference builder, being text and roughly 50 KB, and whether the
four =*_original= spreadsheets join the deposit or the #37 manifest wording is
corrected.

* The =.gitignore=

The specification settled on #29 while resolving #37 is implemented as written:
ignore everything and whitelist by extension; never =.rds=, =.rda=, =.rdata=,
=.qs=, =.qs2=; never PDFs nor anything generated; =SHA256SUMS= as a named
exception; =data-raw/= and =data-processed/= excluded and carried by Zenodo.
=Makefile= is the second named exception, for #38.

One deviation of form, not of substance.
The specification says "ignore everything, whitelist by extension", and this
repository's =.gitignore= achieves that with =*.*= on line 1 — which also
excludes Markdown, and is why documents here have to be written in Org to be
versioned at all.
The new file uses =*= followed by =!*/= instead: contents are ignored while git
still descends into directories, so a document is tracked because of what it is
rather than because of a workaround.
*Markdown is therefore tracked in the new repository*, and the four
=quality_reports= Markdown files are in the initial commit unconverted.
